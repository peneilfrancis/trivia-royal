Trivia Royale: Build Guide for Antigravity
Spec and paste-ready prompts for vibe coding the game, one stage per flow. November 2026.
How to use this guide
Build the game in four stages, one prompt per stage, and test and commit to GitHub after each one. Before you start, export the screens from the design canvas as PNGs into a docs/mockups folder (a1-start.png, a2-play-options.png and so on, following the A and B numbers on the canvas) and tell the agent to match them. Paste each prompt into Antigravity's agent chat. If you would rather keep everything in the repo, save this guide as SPEC.md and begin with "Read SPEC.md first and follow it". If you want a rules file that Antigravity loads automatically, check its documentation for the current file name.
Stack and ground rules
Use React, Vite and TypeScript with plain CSS, React Router in HashRouter mode, and no backend. All data lives in the browser's localStorage, which keeps the project simple and lets it deploy free on GitHub Pages. Design every screen on a fixed 1280 by 720 stage and scale that stage to fit the window, so the layout matches the mockups on a laptop or a projector. Use real button and input elements with visible focus outlines, and keep text large enough to read from across a room. Only the game master touches the screen; players just watch.
Look and feel
Font is Montserrat (weights 500 and 800). Page background is #F4F4F4. Cards are yellow #FCCB4D with dark brown text #3B2A00, a soft shadow and 18px rounded corners. Titles are gold #FFB900. Main action buttons are orange #F85A14 with white bold text. The score bar is #D9D9D9 with a 40px gradient strip beneath it (orange, gold, green, blue). Team colors are blue #00A3F5, red #E81A08, green #7DBA00 and gold #FFB900, plus two extra colors for teams five and six, for example purple #7B3FE4 and teal #0FA3A3. For the Start page, use the original start-screen image from the mockups; if you need the mascot and coin on their own, export them as transparent PNGs first.
Data model
type Card = { question: string; answer: string; image?: string };type Game = {  id: string; name: string; theme: string;  categories: [string, string, string, string];  cards: Card[]; // 20 items. index = row * 4 + column. points = (row + 1) * 100  updatedAt: number;};type Team = { id: string; name: string; color: string; score: number };type Session = {  gameId: string; teams: Team[]; used: boolean[]; step: number;  undo: { teamId: string; delta: number }[];};
Saved games are stored as one array under a single localStorage key. A game being created is kept as a separate draft, so a page refresh does not lose work. The Session is never saved with the game, which means every play starts fresh. Keep it in memory, and optionally in sessionStorage so a refresh mid-game recovers.
Stage 1: Scaffold and shared pieces
Paste this prompt: "Create a Vite, React and TypeScript project called trivia-royale using HashRouter. Add the scaled 1280 by 720 stage, the colors and font above as CSS variables, and shared components: YellowCard, OrangeButton, GradientBar, ScoreChip and Modal. Add a storage module with functions to list, get, save and delete games and to load and save the draft. Add these routes: / (Start), /play, /create/setup, /create/board, /games, /teams, /game, /card/:index and /ranking. Add a seed function that creates a demo game called Campus Quiz Night with 20 filled sample cards, so I can test play without typing every question. Build the Start page to match docs/mockups/a1-start.png, with the Play button going to /play. Add a README and a .gitignore."
Stage 2: Flow A, create a game
Paste this prompt: "Build the create flow to match the mockups A2 to A7. Play options at /play has two big yellow buttons: Create New Game goes to /create/setup, Saved Games goes to /games, and Back returns to Start. Setup asks for a game name (required), a theme (optional) and four category titles (all required). Next creates the draft and opens the board editor at /create/board. The editor shows the board with category titles across the top and 100 to 500 down the side. Each cell is marked Filled when both question and answer are typed, otherwise Empty, with a counter such as 12 / 20 cards filled. Clicking a cell opens the card editor with a header like SCIENCE · 300 POINTS, a question box, an answer box, an optional image button, and Cancel and Save Card buttons. Question and answer are required to save a card. Images, if added, must be resized to about 800 pixels wide and compressed so localStorage does not fill up. The Save Game button is allowed even when cards are missing, so a half-finished game can be saved. It opens a dialog with the game name prefilled. If the name already belongs to a different game, ask whether to replace it or rename. After saving, go back to Start. Back from the editor warns about unsaved changes. Edit on the saved games list loads that game into the same screens, and saving updates the same game instead of making a copy."
Stage 3: Flow B, play a game
Paste this prompt: "Build the play flow to match mockups B3 to B10. The Saved Games page lists each game with its name, theme and a count like 20 / 20 cards filled, plus Play, Edit and Delete buttons. Play is disabled until all 20 cards are filled. Delete asks for confirmation. If there are no games yet, show a friendly message with a Create New Game button. Team setup asks for the number of teams (2 to 6, default 4) and shows a name box for each team in its color. A blank name uses the color name, and team names must be different. Start Game opens the board at /game. The board shows the categories, the point labels and clickable cells, with the score bar at the bottom showing each team's name above its colored score chip. Add a small End Game button in the top corner. Clicking a cell opens the card screen with the category, the points, the question and the image if there is one, and a Show Answer button. Showing the answer marks the card as used. Back to Board returns to the board with that cell dimmed and unclickable. Score chips work like this: tap the big number to type an exact score (whole numbers, negatives allowed; Enter confirms, Escape cancels), and use the minus and plus buttons to change the score by the step shown in the middle. Tap the step number to change it. The step starts at 100 on the board and switches to the card's points when a card is open. Add an Undo button near the score bar that reverses the last score change. The game ends automatically when all 20 cards are used, or when End Game is confirmed in a dialog. The ranking page sorts teams from highest score to lowest. Teams with equal scores share a rank (1, 1, 3) and a tie for first shows a Tie label. Show the top three on a podium (fewer if there are fewer teams) and the rest in a list. Play Again restarts the same game with the same teams, all cards unused and scores at zero. Back to Home returns to Start."
Stage 4: Polish and GitHub
Paste this prompt: "Check that the stage scales cleanly on small laptops and full-screen projectors. Make every screen usable with the keyboard. Handle localStorage being full or blocked by showing a clear error. Add Export and Import for saved games as JSON files so games can be backed up or shared. Configure the project for GitHub Pages by setting the Vite base to the repository name and adding a GitHub Actions workflow that builds and deploys on every push to main. Write a README with a short description, screenshots, how to run it locally, and how to deploy."
On GitHub, create the repository first, commit after every stage with a clear message, and turn on Pages with GitHub Actions as the source once Stage 4 is done. Add a license file if you want others to reuse it.
Gaps in the mockups
A few things the agent needs are not drawn on the canvas, so the prompts above add them: the End Game button on the board, the Undo button, the delete confirmation, the empty state on the saved games list, and the unsaved changes warning. Tell the agent to keep these in the same yellow and orange style. The top-left cell of the board is blank in the mockups, so ask the agent to leave it empty unless you decide what your original PLAY label should do there.
Test it before you share it
Create a game, save it, refresh the page and confirm it is still in the list. Edit it and confirm the name does not duplicate. Play with two teams and then with six. Type a score, use plus and minus, and undo. Finish a game with a tie and check the ranking labels. Delete a game and confirm it is gone.
